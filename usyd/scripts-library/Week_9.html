Windows users must adapt commands accordingly. --- ### Task 1: HTTP(S) Traffic Analysis via MITMproxy In this task, we will configure an Android emulator to route its traffic through a proxy running on our host machine, allowing us to inspect encrypted HTTPS traffic. #### 1. Start MITMproxy on Host (macOS) First, find your local IP address and start `mitmweb` to listen on that interface: ```bash IP=$(ipconfig getifaddr en0) echo "Your Host IP is: $IP" mitmweb --listen-host "$IP" --listen-port 8080 ``` Keep this terminal open. The web interface will launch automatically at `[http://127.0.0.1:8081](http://127.0.0.1:8081)`. #### 2. Install the MITMproxy CA Certificate on Android We need the Android device to trust the proxy's certificate to intercept HTTPS traffic: ```bash # Copy the cert to your current directory cp ~/.mitmproxy/mitmproxy-ca-cert.cer mitmproxy-ca-cert.cer # Push it to the emulator's Download folder adb push mitmproxy-ca-cert.cer /sdcard/Download/mitmproxy-ca-cert.cer # Ensure it's readable adb shell "chmod 644 /sdcard/Download/mitmproxy-ca-cert.cer" ``` Now, on the Android emulator: 1. Go to **Settings** → **Security** → **Encryption & credentials** → **Install a certificate** → **CA certificate**. 2. Select **"Install anyway"** if prompted. 3. Navigate to the **Downloads** folder and select `mitmproxy-ca-cert.cer` to install it. #### 3. Configure Android to Use the Proxy We can automate the proxy configuration using `adb` instead of navigating the GUI: ```bash IP=$(ipconfig getifaddr en0) echo "Setting proxy to $IP:8080..." adb shell settings put global http_proxy "$IP":8080 adb shell settings put global https_proxy "$IP":8080 # Verify settings adb shell settings get global http_proxy adb shell settings get global https_proxy ``` #### 4. Verify Traffic Interception 1. Open **Chrome** on the Android emulator and search for `cyber`. 2. On your host machine, check the MITMproxy web interface at `[http://127.0.0.1:8081/#/flows](http://127.0.0.1:8081/#/flows)`. You should see the HTTPS requests being captured and decrypted. #### 5. Explore Further (with another app) Try the same method for another app. Launch a different app and monitor its network requests in the `mitmproxy` web interface to see how it communicates. --- ### Task 2: Instrumenting a Basic C Application (Kali VM) In this task, we will use Frida to hook a standard C library function (`rand`) in a simple compiled program. #### 1. Compile the Target Program Open **Terminal Tab #1** on your Kali VM and compile the provided C code: ```bash gcc exercise.c -o a.out ``` #### 2. Set up Frida Environment Open **Terminal Tab #2** and set up a Python virtual environment for Frida: ```bash python3 -m venv venv source venv/bin/activate pip install frida-tools ``` #### 3. Run the Target Program In **Terminal Tab #1**, start the program: ```bash ./a.out ``` #### 4. Attach Frida In **Terminal Tab #2**, attach Frida to the running process: ```bash frida a.out ``` Once the Frida REPL opens, paste the following JavaScript hook. This script intercepts calls to `rand()` and forces it to always return `0`: ```javascript Interceptor.attach(Module.getGlobalExportByName("rand"), { onEnter: function () { console.log("rand() called"); }, onLeave: function (retval) { retval.replace(0); } }); ``` #### 5. Observe the Results Go back to **Terminal Tab #1** and interact with the `a.out` program. You will notice that the "random" numbers are no longer random, and the encryption (if based on `rand()`) is now predictable. --- ### Task 3: Android Instrumentation with Frida Hooking This task demonstrates how to override a Java method in a running Android app to change its behavior. #### Prerequisites: * **AVD:** Pixel 9 running Android 16 (Google APIs, NOT Google Play). * **Host:** macOS with Python 3.x. * **Frida version:** 17.4.0 (matched on both host and device). #### Step 1: Install Frida Server on Android Emulator ```bash # 1. Download the correct server binary wget https://github.com/frida/frida/releases/download/17.4.0/frida-server-17.4.0-android-arm64.xz # 2. Decompress it unxz frida-server-17.4.0-android-arm64.xz # 3. Push to the device and make executable adb push frida-server-17.4.0-android-arm64 /data/local/tmp/frida-server adb shell "chmod 755 /data/local/tmp/frida-server" # 4. Run adb shell as root adb root # 5. Run the server as root in the background adb shell "nohup /data/local/tmp/frida-server &" ``` #### Step 2: Install Frida Tools on Host ```bash pip install frida==17.4.0 frida-tools==14.4.5 ``` #### Step 3: Install and Launch Target App ```bash adb install task4.apk ``` Launch the `frida_test` app on your emulator. #### Step 4: Prepare the Hook Script (`override.js`) Save the following code as `override.js`. This script finds the `my_activity` class and replaces its `fun` method with our own implementation that always passes the arguments `2` and `5`: ```javascript console.log("Script loaded successfully "); Java.perform(function x(){ //Silently fails without the sleep from the python code console.log("Inside java perform function"); //get a wrapper for our class var my_class = Java.use("com.example.a11x256.frida_test.my_activity"); //replace the original implmenetation of the function `fun` with our custom function my_class.fun.implementation = function(x,y){ //print the original arguments console.log( "original call: fun("+ x + ", " + y + ")"); //call the original implementation of `fun` with args (2,5) var ret_value = this.fun(2,5); return ret_value; }}); ``` #### Step 5: Inject the Script This command finds the PID and injects the script: ```bash frida -U -l override.js -f com.example.a11x256.frida_test ``` #### Step 6: Observe the Output In a new terminal, watch the device logs. The hook forces the calculation to be `sum(2+5)` overriding original `sum(50+30)`.
