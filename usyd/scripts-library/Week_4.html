``` ## markdown ### Architecture Overview For this tutorial, we will use a single Ubuntu VM. This VM will act as our web server, running: * **Nginx:** A high-performance web server. * **PHP-FPM:** A process manager to handle PHP requests for Nginx. * **NAXSI:** A WAF module compiled directly into Nginx to inspect and block malicious traffic. * **DVWA:** The vulnerable web application we are protecting. --- ### Step 1: Prepare the Target Ubuntu VM > **Note:** Make sure your Ubuntu VM in Oracle VirtualBox uses the correct network mode so it has internet access and can also be reached from your host system to access the DVWA app running on the VM’s web server. Attach both following adapters to your VM's network: * **NAT:** The VM shares the host’s internet connection (for internet access). * **Host-only Network:** Provides direct local network access between host and VM. VM and host talk directly over the host-only IP range, with no internet by default. IP range: `192.168.56.x`. #### Configuration Steps: 1. **Configure:** Add a second adapter in **VM Settings** -> **Network** -> **Expert** -> **Adapter 2** -> **Host-only Adapter**. 2. **Check the VM's IP Address:** Inside the VM, open a terminal and run: ```bash ip a ``` *(or `ip addr show`).* Look for an interface (e.g., `enp0s8`, `enp0s9`) with an IP address like `192.168.56.x`. This is the VM’s Host-only network IP. 3. **Port Forward from VM to Host using SSH tunneling:** Run this command in your host machine terminal: ```bash ssh -L 8888:127.0.0.1:80 @ -N ``` 4. **Access:** Browse to `http://localhost:8888/dvwa` from the host machine browser, connecting directly to the VM's DVWA app running on port 80. #### Connection Flow: ```text [Ubuntu VM: [http://192.168.56.101:80](http://192.168.56.101:80)] │ ▼ [VirtualBox Host-only Adapter] │ │ (SSH Tunnel Port Forwarding: 127.0.0.1:8888 ← 192.168.56.101:80) ▼ [Host Browser: [http://127.0.0.1:8888](http://127.0.0.1:8888)] ``` The first and only step is to run a single automated script. This script will handle all the necessary installations and configurations as described in the tutorial guide, including: * Installing all required dependencies. * Downloading and compiling Nginx from source with the NAXSI module. * Installing and configuring PHP-FPM. * Downloading and setting up DVWA. * Configuring Nginx to serve DVWA and apply the NAXSI rules. * Creating a systemd service to manage Nginx easily. Log in to your Ubuntu VM and run the installation script. #### Supported Platforms: * `ubuntu-24.04.3-desktop-arm64` / `ubuntu-24.04.3-desktop-amd64` * `ubuntu-25.04-desktop-arm64` The output of the unattended installation script should display a series of structured status messages culminating in a clear confirmation indicating that DVWA, NGINX, PHP-FPM, and NAXSI were successfully installed, configured, and are ready for use with default credentials and access instructions provided. After the script finishes, your environment will be ready for the demonstration checkpoints. --- ### Step 2: Verifying the Setup & NAXSI Functionality Now, let's go through the checkpoints to demonstrate that everything is working as expected. #### Checkpoint 1: Start & Stop NGINX in Target VM The script automatically starts and enables the Nginx service. You can verify its status: ```bash # Check status sudo systemctl status nginx --no-pager --quiet # Stop the service sudo systemctl stop nginx # Start the service again sudo systemctl start nginx ``` #### Checkpoint 2: Show the PHP Config File Open a web browser on your host machine. " | sudo tee /var/www/html/info.php ``` Now, in your host machine browser, navigate to `http://localhost:8888/info.php`. You should see the detailed PHP configuration page. #### Checkpoint 3: Demonstrate NAXSI Blocking from Command Line in Target VM NAXSI is installed in blocking mode by default. We can test it with `curl`. 1. Open two terminals connected to your Ubuntu VM. 2. In the first terminal, watch the Nginx error log in real-time. This is where NAXSI logs blocked requests: ```bash sudo tail -f /var/log/nginx/error.log ``` 3. In the second terminal, send malicious-looking requests: ```bash # Test a simple XSS payload curl 'http://localhost/?q=>' # Test a simple SQLi payload curl "http://localhost/?id=1'%20or%20'1'%3D'1'%20%23" ``` 4. Observe the output in the first terminal. You should see log entries from NAXSI indicating it has blocked the requests with specific rule IDs (e.g., `id:1000`, `id:1302`). The `curl` commands will receive a `"Request Blocked by NAXSI"` response. #### Checkpoint 4: Log in to DVWA In your host machine browser, navigate to your DVWA instance (e.g., `http://localhost:8888/dvwa/login.php`). You should be able to log in with the default credentials (`admin`/`password`). Don't forget to create/reset the database via the `/setup.php` page first if needed. --- ### Step 3: Demonstrating WAF Evasion with Learning Mode Now, we'll show how NAXSI can be configured to allow traffic, which is useful for tuning the WAF to avoid blocking legitimate requests. #### Checkpoint 5 & 6: XSS and SQLi Attacks in DVWA ##### Changing DVWA Security to LOW: 1. In DVWA, log in as an admin user. 2. Click the **DVWA Security** section from the left menu. 3. Set the **Security Level** dropdown to **LOW**. 4. Click **Submit** to apply the change. This adjustment ensures all vulnerabilities, including SQL Injection and Stored XSS, are exposed in their most basic, demonstration-ready form, enabling WAF rules to trigger clearly. ##### Next Steps After Setting to LOW: 1. In DVWA, navigate to the **SQL Injection** page and attempt an injection like: ```sql 1' or '1'='1' # ``` 2. Navigate to the **XSS (Stored)** page and attempt to submit a script like: ```html ``` 3. In both cases, the request should be blocked by NAXSI, and you will see corresponding entries in `/var/log/nginx/error.log`. #### Checkpoint 7: Switch to Learning Mode and Bypass the WAF 1. On the Ubuntu VM, edit the NAXSI rules file to enable Learning Mode: ```bash sudo nano /etc/nginx/naxsi/naxsi.rules ``` 2. Locate the line containing `#LearningMode;`. 3. Remove the `#` at the beginning of the line to uncomment it. The line should look like this after editing: ```text LearningMode; ``` 4. Save and exit the file. 5. Reload Nginx to apply the new configuration: ```bash sudo systemctl restart nginx ``` 6. Repeat the XSS and SQLi attacks inside the DVWA web interface. 7. This time, the attacks should succeed. The page will execute the SQL query or store the XSS payload. 8. Check `/var/log/nginx/error.log` again. You will see that NAXSI still logs the attacks, but it prefaces the log entry with `NAXSI_FMT: LEARNING`. This shows it detected the threat but did not block it, allowing an administrator to create whitelist rules for legitimate traffic that might accidentally trigger the WAF. --- This completes all the required checkpoints for the tutorial, demonstrating a fully functional Nginx/NAXSI setup and the core principles of WAF operation. ```
